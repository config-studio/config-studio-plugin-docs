# Спецификация Манифеста `plugin.json` 📄

Файл `plugin.json` — это декларативный паспорт плагина, содержащий метаданные, точку входа, запрашиваемые системные привилегии, зависимости, настройки интеграции в интерфейс и конфигурацию встроенных бинарников агента.

---

## 🔍 Справочник всех полей манифеста

| Поле | Тип | Обязательное | Описание | Пример |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `string` | **Да** | Уникальный ID плагина (`a-z`, `0-9`, `-`, `_`). Должен совпадать с именем директории плагина. | `"servers"` |
| `name` | `string` | **Да** | Название плагина по умолчанию (если не переопределено в `locales`). | `"Servers & Fleet Manager"` |
| `version` | `string` | **Да** | Версия по стандарту SemVer (`MAJOR.MINOR.PATCH`). | `"1.4.0"` |
| `description`| `string` | **Да** | Описание возможностей плагина для каталога и настроек. | `"Управление парком серверов"` |
| `author` | `string` | Нет | Имя автора или организации разработчика. | `"Config Studio Team"` |
| `homepage` | `string` | Нет | Ссылка на репозиторий или документацию плагина. | `"https://github.com/..."` |
| `icon` | `string` | Нет | Иконка плагина из библиотеки [Lucide Icons](https://lucide.dev/icons) (`server`, `terminal`, `globe` и др.). | `"server"` |
| `entry` | `string` | **Да** | Относительный путь к главному JavaScript-файлу плагина. | `"main.js"` |
| `css` | `string` | Нет | Относительный путь к файлу стилей CSS (инжектируется при старте). | `"style.css"` |
| `styles` | `string[]`| Нет | Список файлов стилей CSS для одновременного подключения. | `["style.css", "themes.css"]` |
| `permissions`| `string[]`| Нет | Список запрашиваемых разрешений ядра и хоста (см. белый список). | `["ui.panels", "secrets", "fs"]` |
| `capabilities`| `string[]`| Нет | Алиас для поля `permissions` (поддерживается для обратной совместимости). | `["ui.panels"]` |
| `dependencies`| `object` | Нет | Словарь обязательных (жестких) плагинов с версиями SemVer. Без них плагин не сможет запуститься. | `{"ssh-client": ">=1.0.0"}` |
| `optionalDependencies`| `object` | Нет | *(v2.0.0+)* Словарь рекомендуемых (мягких) плагинов-расширений. Предлагаются к установке в 1 клик, но не блокируют запуск плагина. | `{"yaml-formatter": ">=1.0.0"}` |
| `providesServices`| `string[]`| Нет | Список межплагинных сервисов, регистрируемых плагином в шине RPC. | `["fleet-manager"]` |
| `fileMatches`| `string[]`| Нет | Маски файлов, при открытии которых активируется тулбар и действия. Кнопки тулбара автоматически наследуют эти маски. | `["servers.yaml", "nginx.conf"]` |
| `locales` | `object` | Нет | Встроенные словари локализации названия, описания и интерфейса (`ru`, `en`). | `{"ru": {...}, "en": {...}}` |
| `localization`| `object` | Нет | Декларация плагина как **UI Language Pack** для всего интерфейса редактора. | `{"code": "de", "name": "Deutsch", ...}` |
| `actionToolbar`| `object`| Нет | Конфигурация сплит-кнопки панели действий `[ ▶ Action | ▾ ]`. | См. раздел тулбара |
| `agent` | `object` | Нет | *(v2.3.1+)* Декларация встроенного удаленного агента (Smart Embedded Agent) для прямой установки из `.cspkg`. | См. раздел встроенного агента |
| `settings` | `array` | Нет | Декларативная схема параметров конфигурации плагина для авто-генерации UI. | См. раздел настроек плагина |
| `minAppVersion`| `string`| Нет | Минимальная версия ядра Config Studio для работы плагина. | `"2.3.6"` |

## 🛡️ Модель Разрешений и Безопасность (Zero Trust / Fail-Secure)

Config Studio использует строгую модель безопасности **Zero Trust**: при установке плагина пользователь видит диалог согласия (**Plugin Consent Dialog**), где каждая привилегия проверяется и классифицируется по уровню риска.

### Официальный белый список разрешений:

| Разрешение | Уровень риска | Назначение |
| :--- | :--- | :--- |
| `ui.*`, `ui.panels` | 🟢 **Safe** | Добавление сплит-панелей, нижних панелей и элементов шапки. |
| `contextmenu` | 🟢 **Safe** | Добавление кастомных пунктов в контекстное меню проводника файлов. |
| `toolbar` | 🟢 **Safe** | Интеграция сплит-кнопок быстрых действий в верхнюю панель инструментов. |
| `fs`, `fs.read` | 🔵 **Low risk** | Чтение файлов проекта и конфигураций в рабочей директории. |
| `fs.write` | 🟡 **Medium risk** | Запись, изменение и создание конфигурационных файлов на диске. |
| `network`, `network.bind` | 🟡 **Medium risk** | Запуск локальных веб-серверов и отправка сетевых HTTP-запросов. |
| `service:<name>`, `service.<name>` | 🟡 **Medium risk** | Вызов API межплагинного сервиса `<name>` через безопасную Proxy-шину. |
| `service:*` | 🟡 **Medium risk** | Доступ ко всем зарегистрированным межплагинным сервисам. |
| `shell.exec`, `terminal.exec`| 🔴 **Critical (High)** | Выполнение системных консольных команд на хосте через ядро. |
| `remote.exec` | 🔴 **Critical (High)** | Удаленное выполнение команд по SSH на серверах парка. |
| `secrets`, `secrets.access` | 🔴 **Critical** | Доступ к защищенным паролям, токенам и SSH-ключам из OS Keychain / Vault. |
| `*` | 🔴 **Critical (Full)** | Полный неограниченный доступ ко всем системам редактора и хоста. |

> ⚠️ **Принцип Fail-Secure:** Любые неизвестные или кастомные разрешения, не входящие в спецификацию Config Studio, автоматически помечаются как **Критический риск (`Unknown / High Risk`)**. Ядро блокирует их скрытое выполнение и выводит предупреждающий красный баннер в окне установки.

## 🔗 Межплагинные Зависимости (`dependencies` и `optionalDependencies`)

Config Studio поддерживает трехуровневую модульную архитектуру:
1. **Автономные плагины:** Работают независимо и не требуют сторонних модулей.
2. **Обязательные зависимости (`dependencies`):** Жестко необходимые плагины-провайдеры сервисов (например, SSH-транспорт или парсер AST).
3. **Необязательные зависимости (`optionalDependencies`, v2.0.0+):** Рекомендуемые модули расширения (линтеры, темы, дополнительные форматировщики), обогащающие функционал плагина при наличии.

```json
{
  "dependencies": {
    "ssh-client": "^1.2.0"
  },
  "optionalDependencies": {
    "yaml-formatter": ">=1.0.0",
    "theme-high-contrast": ">=1.0.0"
  }
}
```

### 📊 Сравнение: Hard vs Soft зависимости

| Параметр | Обязательные (`dependencies`) | Необязательные (`optionalDependencies`) |
| :--- | :--- | :--- |
| **Поведение при отсутствии** | Блокирует запуск плагина (статус ошибки зависимости) | Плагин запускается и работает штатно в базовом режиме |
| **Экран согласия (Consent Dialog)** | Выделяется янтарным предупреждением с требованием установки | Выделяется фиолетовой карточкой с **чекбоксами выборочной установки** |
| **Порядок загрузки (DAG)** | Провайдер всегда загружается раньше потребителя | Если опциональный плагин включен, он также загружается раньше потребителя |
| **Защита от удаления (Cascade)** | Защищен: нельзя удалить или отключить провайдер (`409 Conflict`) | **Разрешено**: отключение или удаление мягкой зависимости не блокируется |
| **Вызов в коде** | `await services.get(name, consumerId)` (выбрасывает ошибку при отсутствии) | `await services.getOptional(name, consumerId)` (возвращает `null`, если сервис недоступен) |

## ⚡ Предоставление сервисов (`providesServices`)

Если ваш плагин предоставляет API-сервис для других плагинов (например, SSH-соединение или управление инвентарем):

```json
"providesServices": ["fleet-manager"]
```

В коде плагина вы регистрируете реализацию:
```javascript
window.ConfigStudio.services.register('fleet-manager', {
  getServers: async () => { /* ... */ },
  pingHost: async (hostId) => { /* ... */ }
}, 'servers');
```

## 🌍 Локализация (`locales` и `localization`)

### 1. Автономная локализация плагина:
Чтобы название, описание и строковые константы плагина автоматически переводились на язык пользователя:

```json
"locales": {
  "ru": {
    "name": "Флот серверов & Инвентарь",
    "description": "Управление парком серверов, servers.yaml, SSH/SFTP, встроенный агент и отправка файлов",
    "allNodes": "Все узлы",
    "addServer": "Добавить узел"
  },
  "en": {
    "name": "Servers & Fleet Manager",
    "description": "Centralized server inventory, servers.yaml, native SSH/SFTP and agent integration",
    "allNodes": "All Nodes",
    "addServer": "Add Node"
  }
}
```

### 2. Языковые пакеты интерфейса (UI Language Packs):
Если плагин добавляет в Config Studio поддержку нового языка для всего редактора:

```json
"localization": {
  "code": "de",
  "name": "Deutsch",
  "flag": "🇩🇪",
  "translations": {
    "settings": "Einstellungen",
    "save": "Speichern"
  }
}
```
После установки в настройках редактора появится новый пункт выбора языка с флагом `🇩🇪` и бейджем `Pack`.

### 3. Вынесение локализации в `local.json` и `localization.json` (Core v2.3.6+):
Для сохранения чистоты и компактности `plugin.json` сотни строк переводов больше не нужно держать внутри самого манифеста!

Ядро Config Studio при монтировании папки плагина или пакета `.cspkg` автоматически ищет файлы локализации:
- `local.json`, `localization.json` или `locale.json` в корне плагина.
- `locales/<lang>.json` (например, `locales/ru.json`, `locales/en.json`, `locales/de.json`) в папке `locales/`.

#### Поддерживаются два формата `local.json`:
**Вариант А: Структурированный языковой пакет (`LanguagePackDef`)**
```json
{
  "code": "de",
  "name": "Deutsch",
  "flag": "🇩🇪",
  "translations": {
    "welcome": "Willkommen",
    "settings": "Einstellungen",
    "save": "Speichern"
  }
}
```

**Вариант Б: Плоский словарь переводов (`Flat Map`)**
```json
{
  "welcome": "Willkommen",
  "settings": "Einstellungen",
  "save": "Speichern"
}
```
Если в корне плагина с ID `lang-de` лежит плоский `local.json`, ядро автоматически определит код языка `de`, свяжет словарь с именем плагина и зарегистрирует полноценный языковой пакет. Это позволяет легко переводить интерфейс сторонним переводчикам без риска нарушить метаданные плагина.

## 🎯 Панель действий 1-Click Action Toolbar (`actionToolbar`)

Для плагинов, автоматизирующих запуск задач (Makefile, Docker Compose, сборщики):

```json
"actionToolbar": {
  "primaryAction": "build",
  "targets": [
    { "id": "build", "label": "build (Default)" },
    { "id": "test", "label": "test" },
    { "id": "deploy", "label": "deploy" }
  ],
  "hotkey": "F5"
}
```
- Создает в верхней панели сплит-кнопку `[ ▶ Run: build | ▾ ]`.
- Клик по левой половине мгновенно запускает действие в 1 клик (или по горячей клавише `F5`).
- Стрелка `▾` открывает выбор других целей.
- Благодаря `fileMatches` кнопка отображается **только** для соответствующих файлов, сохраняя нулевой визуальный шум (Zero-Clutter) на обычных конфигах.

## 🤖 Встроенный удаленный агент (`agent`) и Двойное Версионирование

Начиная с **Config Studio v2.3.1+** и плагина **Servers & Fleet Manager v1.4.0+**, плагины могут включать скомпилированные бинарники демонов удаленных агентов прямо внутрь пакета `.cspkg`.

### Преимущества архитектуры Smart Plugin-Embedded Distribution:
1. **Air-Gapped Ready:** Удаленным серверам не требуется выход в интернет или GitHub. Файл агента стримится ядром Config Studio напрямую из ZIP-контейнера `.cspkg` в SFTP-канал целевого сервера без промежуточной распаковки на клиентский диск.
2. **Нулевой мусор на клиенте:** Бинарники демона читаются потоково `io.Reader` и пересылаются на сервер атомарно.
3. **Бесплатные обновления (SemVer):** При выходе нового релиза агента инкрементируется версия пакета плагина (`1.4.0` → `1.4.1`), и менеджер плагинов автоматически предлагает обновление через стандартный каталог.
4. **Безопасная ротация и откат:** При деплое на удаленном сервере старый бинарник сохраняется как `.bak`, новый бинарник запускается во временном файле на том же разделе диска (для предотвращения ошибки `EXDEV`), проверяется эндпоинт `/api/health`, и при сбое происходит мгновенный автоматический откат.

### Пример декларации в `plugin.json`:
```json
{
  "name": "Servers & Fleet Manager",
  "version": "1.4.0",
  "agent": {
    "version": "2.3.0",
    "commit": "1fe3dc3",
    "binaries": {
      "linux-amd64": {
        "path": "agents/config-studio-agent-linux-amd64",
        "sha256": "32134f049e8760c7c9bf78c57ff707ad808e6504ce6ada69e60badc5c66e32a4"
      },
      "linux-arm64": {
        "path": "agents/config-studio-agent-linux-arm64",
        "sha256": "0b0b53947e9dcdc00d6ef8dd6d55a43f8a04b4d2589c60fd8e21dbe78afa22f2"
      }
    }
  }
}
```

### Принцип двойного версионирования:
- **Версия плагина (`version`)**: SemVer интерфейса, панелей и функционала плагина (например, `1.4.0`).
- **Версия агента (`agent.version`)**: Версия бинарного демона `config-studio-agent`, инжектируемая компилятором через `-ldflags` (например, `2.3.0`).
- **Сверка целостности (`sha256`)**: Ядро Config Studio сверяет SHA-256 хеш бинарника перед отправкой по SFTP, гарантируя защиту от повреждения данных или подмены.
